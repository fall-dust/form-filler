# 表单填写器 · Windows 客户端

![image-20260918230736605](https://fallingdust-typora.oss-cn-hangzhou.aliyuncs.com/image-20260918230736605.png)

Electron + React + Playwright 的表单自动填写客户端，核心是「拿到表单 HTML → 生成提示词 → 问 AI 拿到题目/答案配置 → 一键填写」。表单 HTML **不用手工复制**：左栏填好「目标链接」→ 点「**启动浏览器**」打开页面 → 点「**抓取当前页 HTML**」把源码取回来（抓取只在你要抓时才抓，且会等页面真正加载好再抓）。题目与答案配置走**手动提示词通道**：生成提示词 → 复制 → 交给任意 AI → 把返回的 JSON 贴回导入。详见 [客户端方案.md](客户端方案.md)（设计）；[需求文档.md](需求文档.md) 为最初 Python CLI 需求，已废弃。

## 使用流程

> 界面为「左侧配置栏 + 右侧步骤流水线」布局：左侧收纳目标链接/浏览器选项/任务操作等低频配置（**浏览器开关与抓取在右侧步骤 1，不重复放两份**），右侧按功能流分四步（表单 HTML → 生成题目 → 生成答案 → 校对与运行），完成的步骤自动折叠成一行摘要。底部常驻「开始填写」操作条。顶部标签栏就是任务列表：`＋` 新建、`×` 删除（进「历史任务」，可撤销）、双击重命名、拖拽排序；**改动自动保存到本机，没有「保存」按钮**；多个任务可同时运行，各自弹出独立浏览器窗口并行跑。
>
> **步骤对钩 = 「当前有效」，不是「历史上做过」**：一旦上游内容变了（重新抓取页面、手改 HTML、换了题目），下游步骤的对钩会**自动收回**并退回待办 —— 流程顶部给出原因，并直接提供「对当前页面重新生成题目」入口。所以不会出现「第 2 步亮着 ✓，但那 19 道题其实来自上一页」的假完成。收回只改状态，**不删数据**，旧内容也仍在「任务管理 → 历史版本」里；若你确认只是时间戳之类的细微差异，可点「其实还是同一页」把对钩复原。

1. **拿到表单 HTML**（步骤 1）：两种方式，**不用开开发者工具**——
   - **抓取（推荐）**：左栏填好「目标链接」→ 在右侧**步骤 1** 点「**启动浏览器**」把页面打开（**只打开、不抓取**，所以题目/答案还没生成也能先开；需要登录就先登录，多页问卷还可以先翻到要采集的那一页）→ 等页面显示出来 → 点「**抓取当前页 HTML**」，源码即被填进文本框（含表单控件的 iframe 一并收录、`<script>/<style>` 等噪音剥掉）。
     - 抓取**只在你说抓的时候才抓**：打开浏览器不会顺带抓取；点抓取后会先**等页面真正加载好**（最多 15 秒），没长好就如实提示，绝不抓回空壳。
     - **覆盖前自动存档**：新抓的这一页覆盖之前，上一份 HTML 连同当时的题目会自动存进「任务管理 → 历史版本」里的「抓取前」版本，想回到上一页随时回滚（**连页面一起还原**）。
     - 抓取成功后，会用页面标题**自动给任务起个名**；你自己改过名字之后，就不会再被自动改名。
   - **手工粘贴**：把表单 HTML 粘进文本框，粘贴完自动折叠。
   左栏「**浏览器会话**」区显示窗口状态与当前 URL，并提供「结束会话 / 清除登录态」（**只管会话**）；「启动浏览器」「抓取当前页 HTML」在右侧步骤 1，只此一处、不重复。浏览器**始终以可见窗口启动**（多页问卷要你亲手点「下一页」，登录与填写过程也都看得见）—— 原先的「headless（无头）」开关与此机制冲突，已移除。2. **拿到题目配置**（步骤 2，手动通道）：展开「生成提示词」→ 复制 → 拿去问任意 AI → 把返回的 JSON 贴回导入。
3. **（可选）生成答案**（步骤 3）：填「作答目标/情境」→ 生成答案提示词 → 同样复制给 AI → 贴回导入。
4. **填/校答案**（步骤 4）：题目表格里逐题填或选答案（也可直接贴入 AI 返回的答案）。
5. **运行**：点底部「开始填写」，浏览器弹出并逐题填写；**每题的填写状态实时亮在表格行内**（filled/missing/failed 徽章），报告汇总与失败截图折叠展示在表格下方。默认填完浏览器保持打开，你人工核对后手动提交；也可在左栏勾选「**填完自动提交**」（仅当全部题目填写成功才会自动点击提交按钮）。

**断点续填**：左栏勾选「**只填未完成项（续填）**」后，本次只重填上次没成功的题（上次已填好的题跳过），状态按任务分别记录。

**多页问卷（点「下一页」才显示后面的题）**：**每一页各自存档、一页一页填**，翻回旧页不必再让 AI 重新生成题目 ——
1. 第 1 页：填好目标链接 → 点步骤 1 的「**启动浏览器**」→ 页面显示出来后点「**抓取当前页 HTML**」→ 生成题目/答案 → 点底栏「开始填写」；
2. 翻到下一页：点步骤 1 里识别到的「**下一页**」按钮（识别到的翻页按钮会显示出来，点它即在浏览器里翻页），或自己在浏览器里点 —— 然后点「**抓取当前页 HTML**」；也可以直接点「**翻「下一页」并抓取为新页**」一次做完；
3. 抓到的新页会**自动存成一份新的「页面存档」**（步骤 1 顶部那条，显示页名与「N 题 · N 答」）。新页起步没有题目：走「生成提示词 → AI → 导入」产出这一页的题目，再点「开始填写」—— **复用同一个浏览器窗口、在当前页接着填**，不会重开回到第 1 页；
4. **翻回旧页**：在浏览器里翻回去再抓一次，或直接点「页面存档」里那一页的 chip 切回来 —— 它的题目与答案原样还在，**不用重新生成**。判定按内容走：一字不差就只更新这份 HTML；结构相同（只是重新渲染过、随机前缀变了）也认作同一页，题目与答案继续有效。
   - 页名**双击**可改；chip 上的 `×` 删除该页（只剩一页时等价于清空这一页，任务永远至少有一页）。
   - 多页问卷里重复出现的题（每页都问一次的那种）在生成题目时会**自动带入上一页的作答**，可在第 4 步改。

**识别到的「翻页按钮」**：识别是**只读**的（不改页面内容、不点任何东西），识别到的按钮只是**显示出来**；**只有你点它才会翻页**。识别时就把「提交 / 完成 / 返回 / 上一步 / 取消」这类文字排除在外 —— 宁可漏认，绝不误点。按钮当前禁用（比如本页还有必答项没填）会标注「（不可用）」。主框架里没有时会去子框架（iframe 内嵌问卷）里找。

**「抓取前」自动存档仍在**：每次抓取前都会把上一份 HTML 与当时的题目存进「任务管理 → 历史版本」（标着「抓取前」），回滚可连页面一起还原。它与页面存档是**互补**的：页面存档管「按页长期保留」，历史版本管「刚被覆盖掉的那一份」。

左栏「浏览器会话」区显示当前窗口状态；想从头开始点「**结束会话**」（下次运行重新打开、回到目标链接）。手动关掉浏览器窗口也会让会话自动作废（下次运行自动重开）；**目标链接一旦改动，旧窗口即作废**（下次启动/运行按新链接重新打开），避免在错误页面上接着填。

**登录一次长期有效**：每个任务固定用一个自己的浏览器 profile 目录（`<userData>/profile/<任务 id>`），登录信息（cookie）就存在那里 —— 在窗口里登录过一次，之后**关掉窗口、点「结束会话」、甚至改过目标链接**，下次打开都还带着登录态，不用每次重登。换账号或登录态失效时才点左栏「**清除登录态**」（关窗口 + 删该目录）。该目录**含敏感 cookie，不随「导出」外传**。

> 早先那套「勾了『有登录环节』就一直暂停、等你粘贴登录后的新链接」已移除：它与「先启动浏览器再抓取」这条主路重复，且暂停期间「停止」无法中断。

**数据安全**：删除进「历史任务」可撤销（默认保留 30 天，可改为 7/90 天或永久）；导入题目/答案等关键动作会自动留**历史版本**可回滚；侧栏「导出」/「导入配置」用于换机或交接时整体搬迁（导出文件含答案，注意保管）。

## 环境要求

- Node.js ≥ 20（开发环境已用 v26 验证）
- Windows 10/11

## 安装

```bash
npm install
```

> 首次需下载 Electron 二进制（约 100MB）。若只想先跑填写引擎的单测，可 `ELECTRON_SKIP_BINARY_DOWNLOAD=1 npm install` 跳过。

## 常用命令

| 命令 | 说明 |
|------|------|
| `npm run dev` | 开发模式（HMR，启动 Electron 窗口） |
| `npm run test` | 运行填写引擎单元 + 端到端测试 |
| `npm run typecheck:node` | 类型检查 main + preload |
| `npm run typecheck:web` | 类型检查 renderer |
| `npm run build` | 构建 main/preload/renderer 到 `out/` |
| `npm run dist` | 打包安装包 + portable exe（electron-builder，自带瘦身裁剪） |
| `npm run check:browser` | 校验裁剪后的随包 Chromium 仍能正常渲染与填写 |
| `PRUNE_TIER=aggressive npm run dist` | 更激进的体积裁剪（再省约 34 MB，见下） |

## 当前进度

- ✅ **M0 骨架**：Electron 主/渲染进程 + IPC + 安全基线，`npm run dev` 可启动。
- ⚠️ **M1 智能解析**（已移除）：原 cheerio 启发式解析对真实 HTML 不可靠，改由「提示词生成器 + LLM」产出结构化配置。
- ✅ **M2 填写引擎**：Playwright 回退链定位 + 14 类题型填写 + 进度事件 + 失败截图 + 断点续填 + 报告；端到端测试真实填写并回读 DOM 校验通过。
- ✅ **M3 UI 整合**：提示词生成 + 题目/答案导入 + 运行与报告（登录弹窗已由「登录态持久化」取代，见「近期增强」）。
- ✅ **M4 打包**：electron-builder 产出 NSIS 安装包 + portable 单文件 exe；chromium 随包分发到 `resources/browsers/`。
- ✅ **M5 / M6 / M7**：界面重构（步骤流水线）、任务存储改版 —— 详见下方「近期增强」。
- ✅ **M8 / M9**：表单覆盖增强（iframe / 滑条 / 星级 / 开关 / 自定义下拉 / 富文本 + 回读校验）、安装包瘦身。
- ✅ **契约层与单一知识源**（行为零变化的结构性收敛）：新建 `src/shared/contracts/`（跨进程、零 electron 依赖）—— 题型枚举、题型能力注册表、FNV1a 指纹、选中态判定、答案归一化、HTML 摘要各自收敛为**唯一实现**；原先散落四处的题型枚举、两份指纹算法、三份选中态正则、两份 switch 状态读取、两份答案解析全部改为引用同一份，且「有没有人又抄一遍」由**测试**（源码扫描）而非人工 grep 保证。

> 早期版本曾内置「AI 直连」（DeepSeek 秘钥 → 一键生成题目/答案）与「AI 原生化」（页面上自主操作 + 站点记忆）两代 AI 能力，**均已移除**。现在 AI 只通过**手动提示词通道**参与：本工具负责生成提示词与导入校验，具体调哪个 AI 由你决定。

## 近期增强

- **单一知识源：把「同一份知识写了四遍」变成历史**。这一步**不改变任何行为**，只把散落各处的重复定义收敛成一份 —— 否则两侧会各自漂移，后果是「同一个控件，在 A 环节认作下拉、在 B 环节认作文本框」。
  - **新建 `src/shared/contracts/`**（跨进程共享、零 electron 依赖）：`question.ts` 题型枚举与题目结构（原先**四份**：引擎 types、渲染 types、提示词 TYPES、导入清洗 TYPES）；`registry.ts` **题型能力注册表**（`strict` 回读是否严格 / `editor` 界面用什么输入框 / `textLike` / `grouped` / `matchMode`，一处定义、多处派生 —— 新增一种题型只需登记一行，**忘了登记会直接编译报错**）；`hash.ts` FNV1a 指纹（两处**包装格式不同**，都保留：任务指纹带长度前缀，结构指纹不带）；`checked.ts` 「已选中」判定（问卷网 `ws-*`、TDesign `t-*`、Element `el-*`、antd `ant-*` 的规律从此只写一遍）；`answers.ts` 答案归一化（「粘贴导入」与「文件导入」共用同一份规则，否则同一份答案经两条路进来会不一样）；`page.ts` HTML 摘要（正文摘要 / 当指纹用的结构文本）。
  - **注入浏览器的函数也照此办理**：`collectInPage` / `stateInPage` 会被序列化送进页面执行、不能引用模块标识符 —— 它们改为**按参数接收**知识（`evaluate(fn, { …, checkedClsSource })`），而不是内联一份副本靠注释提醒同步。
  - **「有没有人又抄了一遍」由测试保证**：`single-source.test.ts` 用**源码扫描**断言重复定义归零；`contracts.bridge.test.ts`（7 例）保证**两边跑出来的结果真的相同**（只保证「代码里只有一份」还不够）。人肉 grep 会随记忆漂移，测试不会。
- **顺手修掉一个真实的关闭缺陷**：回归时 2 例 e2e **稳定**超时，打点诊断发现业务断言早已通过，卡住的是最后一行 `browser.close()` —— 本环境它**会一直挂着不返回**。而「CDP 优先的安全关闭」早就写好了，只是**私有**在 `session.ts` 里，于是引擎的取消收尾、`openPageAt` 的失败收尾、e2e 收尾共 6 处仍在用裸 `close()`：后果不只是测试超时，更是**孤儿 Chromium 继续占着 profile 目录锁**（下次启动卡在 ProcessSingleton，症状是「莫名其妙再也起不来」）。现已把 `shutdown` 移到 `browser.ts`（与 `launchBrowser` 成对，避免 `session → browser → session` 循环依赖）并全部改用它，该 e2e 文件耗时 **307s → 21.6s**。
- **保存不再被瞬时占用吓退（2026-09-20）**：原子写靠 `rename` 落地，而 Windows 上这一瞬间可能被杀毒实时扫描 / 搜索索引 / 缩略图进程占住句柄，抛 `EPERM`/`EBUSY`/`EACCES`——以前会直接冒泡成「保存失败」，其实几毫秒后就没事了。现在这三类错误会**退避重试**（25/50/75/100/125ms，共 5 次），仍失败才如实报错；`ENOENT` 这类真错误**立即抛出、不重试**，不会被掩盖。`fsx.test.ts` 6 例覆盖（含「一直失败要停在上限」与「真错误不重试」）。

- **多页问卷的页面存档 + 翻页按钮识别（2026-09-19）**：多页问卷从此**一页一档**——每页各自留着自己的 HTML / 题目 / 答案（`tasks/<id>/pages/<pageId>.html`），可以一页一页填，翻回旧页直接沿用，**不必再让 AI 重新生成题目**。
  - **抓取自动落页**（`renderer/src/pages.ts` 的 `routeGrab`）：按内容判定 —— 一字不差（精确指纹 `fp`）→ 只更新这一页的 HTML；结构相同、只是重新渲染过（结构签名 `sig`：丢掉全部属性、把 4 位以上数字压成占位）→ 认作同一页并**把题目指纹重盖到新 HTML 上**，题目与答案继续有效；都没命中才**存为新页**。刚建好的任务/清空过的页是「空占位页」，第一次抓取直接填进去，不会凭空多出一页。
  - **识别「下一页」按钮并显示**（`fill-engine/next-button.ts`）：只读扫描按钮/链接，按关键词给「下一页/下一步/继续…」打分，**命中「提交/完成/返回/上一步/取消」的一律排除**，隐藏元素与 0 面积元素也排除，禁用状态照实标注；主框架没有时去子框架找。识别到的按钮在步骤 1 显示成 chip：**点它才翻页**（选择器 → `role=button` 文本 → 文本派发三级回退），另有「**翻「下一页」并抓取为新页**」一次把下一页收进档。
  - 任务存储层保持「顶层 questions/answers 是**当前页的镜像**」，所以填写引擎、快照、导出这些只认一份内容的老代码不必知道「页」的存在；快照连**每一页的 HTML** 一起存，导出/导入也带页。页名可改、可删（只剩一页时是「清空这一页」）；生成题目时会把**上一页里题干与选项完全相同**的题的答案带入（多页问卷常见的重复题）。
- **步骤对钩会回退（2026-09-19）**：对钩从此代表「当前有效」，而不是「历史上做过」。重新抓取页面（或手改步骤 1 的 HTML）后，步骤 2 的题目会被判定为「上一版页面生成的」——对钩自动收回、折叠摘要标注「对应上一版页面，待重新生成」，流程顶部给出原因与「**对当前页面重新生成题目**」按钮（另附「**其实还是同一页**」的活口：时间戳/随机前缀之类的细微差异不必重生成，也不花 AI 额度）。题目一换，步骤 3/4 的答案与「每题都有答案」也一并收回，免得拿上一页的答案去填新页。实现上给任务存了两个内容指纹 —— `questionsFor`（生成题目时的 HTML 指纹）、`answersFor`（生成答案时的题目指纹），判定是纯函数 `src/renderer/src/freshness.ts`；**收回只改状态、不删数据**，旧任务没有指纹时按「当前内容就是它的来源」自动回填一次，判不出来（没有 HTML、没有指纹）就按有效处理、不乱报警。
- **启动浏览器与抓取分为两步（2026-09-19）**：以前「打开并抓取」是一键 —— 点下去浏览器刚打开就抓，而问卷多是前端渲染，常常抓回空壳。现在拆开：**启动浏览器**（`fill:session:open`，**只打开、不抓取**，所以题目/答案还没生成也能先把页面开起来去登录、翻页、看清结构）+ **抓取当前页 HTML**（**只在用户点击时执行**，且先 `waitForGrabReady` 等页面真正长好：`readyState` 不再是 loading 且页面上已出现表单控件或正文，最多等 15 秒；没长好就如实提示，绝不抓空壳）。抓取仍复用同一窗口，不重开、不导航。
- **抓取覆盖前自动存档 → 可回到上一页**：抓取新一页前，上一份 HTML 连同当时的题目会自动存成一份「抓取前」（`pre-grab`）历史版本 —— HTML 放在与快照同名的 `.html` 旁挂文件里，所以列历史版本时不必解析大 HTML。在「任务管理 → 历史版本」点「回滚到此版本」即可**连页面带题目**回到上一页；这类存档不参与自动清理（自动清理只动 `auto`），因此「第一次的记录」不会因为抓了下一页而丢掉。
- **自动为任务命名（2026-09-19）**：抓取成功后，用页面标题给任务起个短名（如「2026 校园招聘登记」），取不到就静默跳过、不打扰抓取主流程。任务配置有 `nameAuto` 标记：只有「程序自动起的名字」（默认名 `任务 N`）才允许被覆盖，**用户亲手改过的名字绝不动**（侧栏改名框、标签栏双击改名都算用户认领）。
- **多页问卷「接着填」（复用浏览器会话）**：每个任务的浏览器窗口在运行结束后被主进程记住；对同一任务**再次运行时会复用该窗口、在其当前页面继续填写**（不重开、不重新导航），于是「翻页 → 抓取本页 → 生成题目 → 再运行」能顺序走完多页表单，而不会重开浏览器回到第 1 页。配套左栏「浏览器」区：显示窗口状态与当前 URL、**启动浏览器**、**抓取当前页 HTML**、**结束会话（重开浏览器）**。会话失效（浏览器被关）或目标链接变更时自动回退为重新打开。
- **自动提交可选（M8.6）**：默认仍为「填完人工核对、手动提交」；左栏新增「填完自动提交」开关（默认关闭、橙色警示样式）。开启后仅当**全部题目填写成功**才自动点击提交按钮（原生 submit → 组件库主按钮 → 按钮文本三级匹配，排除取消/重置类）；存在未完成项时跳过并在报告中说明原因；报告显示「已自动提交 ✓」或未提交原因。点击后还会做**效果验证**（submit 事件 / 网络请求 / 页面跳转 / 按钮变禁用），结论落在报告字段 **`submitConfirmed`** 上（`true` = 已确认页面响应，`false` = 点了但无法确认）；为 `false` 时界面显示「已点击提交（结果未确认）」并写明点的是哪个按钮、请人工核对（常见于异步提交或校验拦截），**绝不谎报成功、也绝不重试点击**。

- **表单覆盖增强（M8）**：**iframe 内表单可定位填写**；新增 5 类题型——滑条 slider、星级评分 rate、开关 switch、**自定义下拉 richselect**（el-select/antd Select 等 div 模拟下拉）、富文本 richtext；面板式日期选择器回退（el-date-picker 等）；**填写后回读校验**（不符自动重填一次，严格题型两次不符判失败并截图）；填写前自动滚动到元素；动态选项懒加载等待。支持题型从 9 类增至 **14 类**，端到端测试 17 题全绿。
- **任务存储改版（M7）**：删除「项目」概念——**任务 = 标签 = 落盘实体**。改动自动保存（顶栏有保存态指示灯，无保存按钮）；`×` 删除进**回收站**可撤销（默认保留 30 天；**界面上叫「历史任务」**，磁盘目录仍是 `trash/`）；导入题目/答案等关键动作自动留**历史版本**，可回滚；旧 `projects/` 配置首次启动自动迁移（原目录备份为 `projects.migrated-*`）。
  - **换机搬迁**：导出/导入走 JSON 单文件，跨机器导入后题目/答案/HTML 一致，且导入是新任务、绝不覆盖本机同名任务；磁盘写入失败会报错并保留待写内容，修好后（或退出前）自动补写。
- **界面重构（M6）**：改为「左侧配置栏 + 右侧步骤流水线」单页布局——完成的步骤自动折叠成摘要；去掉「运行」二级 tab，**填写状态实时亮在题目表格行内**（填一题亮一题），报告/截图/日志折叠展示；「开始填写」常驻底部操作条。
- 任务管理抽屉：任务列表（重命名 / 复制 / 导出 / 清空内容 / 删除）+ 历史版本 + 历史任务（恢复 / 彻底删除 / 保留期设置）。
- 元素定位健壮：单选/多选多级点选回退（普通 check → force → 点 label → **同容器兄弟 label** → JS 派发 click），兼容 Element UI 等隐藏原生 input。
- **选择题「整组优先」定位（2026-09-19）**：回退链里若某条 css 只命中单个选项，引擎会继续探测后续策略、取命中元素最多的一条。专治两类真实坑：① 某些问卷平台（腾讯问卷 wj.qq.com）**同一题每个选项的 name 都不同**、且 name 前缀是框架自动生成的渲染序号，写死 name 只能填到某一个选项、点选后整块重渲染还会直接失配；② AI 把选项逐条写进选择器。现在优先用 `#题目容器 input[type=radio]` 这类稳定写法。
- **定位失败不再空等 30 秒**：所有属性读取都有 2 秒上限，元素被框架重渲染掉时立刻失败并如实报错（此前会默认等满 Playwright 的 30s 才抛错）。
- **下拉浮层识别补 TDesign**：richselect 除 el-select / antd Select 外，新增 `.t-select__dropdown` / `.t-select-option` 等 TDesign 选择器（腾讯问卷的下拉就是 TDesign）；浮层内带搜索框时先输入答案过滤，过滤不到再清空用全量列表兜底。
- 浏览器瘦身：配置 `channel: msedge/chrome` 复用系统浏览器，可省去随包 chromium（约 200MB）。
- 安装包瘦身（M9）：无损裁剪语言包/辅助 exe/Playwright 测试跑器 + `compression: maximum`，安装包 225 MB → 179 MB；裁剪逻辑见 §打包产物，回归用 `npm run check:browser`。
- 左栏布局：说明性长文本改为「一行标题 + 点击展开」的折叠块（`components/SideNote.tsx`，展开状态按标题记在本机），260px 窄列不再被提示占掉半屏。
- 运行失败提示：界面显示红色错误横幅（不再是「无响应」），并把错误写入 `userData/output/error.log`。

### 安装包瘦身（M9）

体积几乎全由「Electron 运行时 + 随包 Chromium」决定，按「只删本项目链路绝对用不到的文件」做无损裁剪：

| 措施 | 落点 | 收益 |
|------|------|------|
| `electronLanguages: [zh-CN, en-US]` | `electron-builder.yml` | 解包 −80 MB（其余 60+ 语言包） |
| 随包 Chromium 只留 zh-CN/en-US 语言包 | `scripts/lib/prune.mjs` | −40.8 MB |
| 删安装器与系统集成辅助 exe（setup / chrome_proxy / pwa_launcher / notification_helper / elevation* / chrome_wer） | 同上 | −22 MB |
| 运行时依赖 `playwright` → `playwright-core`，并删打包副本里的报告/Trace 查看器与类型声明 | `package.json` + afterPack | 解包 −20 MB |
| `compression: maximum`，关闭差分包 | `electron-builder.yml` | 安装包更小（构建约 2 分钟） |

裁剪执行时机：`scripts/bundle-browsers.mjs` 复制浏览器到 `browsers/` 后立即裁一次（缓存更小、后续拷贝更快），`scripts/prune-package.mjs` 作为 electron-builder 的 `afterPack` 钩子在生成安装包前再裁一次，两处口径一致。

**保留不动**的是任何可能被渲染/GPU 路径加载的 DLL（`dxcompiler.dll`、`vk_swiftshader.dll`、`d3dcompiler_47.dll`、`libEGL/libGLESv2`）与 `hyphen-data`。要极限瘦身可开激进档（再省约 34 MB，WebGPU/软件渲染兜底有极小概率受影响）：

```bash
PRUNE_TIER=aggressive npm run dist
```

裁剪结果必须能回归验证 —— 装完打不开是最致命的失败，所以每次改裁剪后都跑一遍：

```bash
npm run check:browser                          # 默认检查 dist/win-unpacked
node scripts/check-bundled-browser.mjs --dir dist/win-unpacked
node scripts/check-bundled-browser.mjs --exe browsers/chromium/chrome-win64/chrome.exe
```

它会用**裁剪后的** `chrome.exe` 真跑一遍「打开页面 → 填写 → 读回 → 截图」，确认中文渲染与自动化都正常。

> 打包时 `scripts/bundle-browsers.mjs` 会把 Playwright 的 chromium 复制进 `browsers/`，随包分发；打包后引擎用 `executablePath` 指向 `resources/browsers/chromium/chrome-win64/chrome.exe`。
>
> 换用系统浏览器可进一步省掉整个随包内核（约 −369 MB）：界面左栏「浏览器」选「系统 Edge / 系统 Chrome」，即配置 `channel: msedge|chrome`。
>
> 国内网络下打包若下载 electron-builder 二进制超时，加镜像：
> `ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/ npx electron-builder`

> Playwright 的 driver 子进程需在 asar 外运行，`electron-builder.yml` 已用 `asarUnpack` 把 `playwright`/`playwright-core` 解到 `app.asar.unpacked/`；否则打包后「开始填写」会因 driver 启动失败而无响应。
>
> 运行失败排查：界面会显示红色错误横幅，错误同时写入 `userData/output/error.log`（`%APPDATA%\表单填写器\output\error.log`）。

> 运行 e2e 前需先 `npx playwright install chromium`。
